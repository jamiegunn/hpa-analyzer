hpa-analyzer
Helm + HPA + JVM-in-container analysis, with its own limits written down.
Start here Using it Reading the report Container Reference Limits

Start here

hpa-analyzer reads a directory containing a Helm chart, its values files and — optionally — a Dockerfile, and writes a plain-text report about three things: whether the HPA arithmetic actually works, whether the requests and limits are coherent, and how a JVM will behave inside the cgroup you gave it. The last one is the part no other tool in the standard stack checks.

Read first This tool is a linter, not an oracle. Everything on this site is written from measured runs of the code in this repository, and the page that matters most is Limits — what it does not do, and what a clean report does not prove. If you only read two pages, read this one and that one.

Install

Python 3.8 or newer, plus PyYAML. That is the whole dependency list.

git clone https://github.com/jamiegunn/hpa-analyzer.git
cd hpa-analyzer
pip install -r requirements.txt

Two entry points exist and they are the same program — python3 hpa-analyzer.py is a thin shim over python3 -m hpaanalyzer. This site uses the module form throughout because it is the one that works from any directory once the repo is on your PYTHONPATH.

Install helm too, if you can. With helm on your PATH the chart is rendered by the real template engine and the report says helm (rendered truth). Without it the tool falls back to static parsing, says so, and rewrites its coverage table to mark every input as statically parsed. Both modes work. They do not always produce the same findings, and that difference is a fact about the tool you should know before two people compare reports — see Your PATH changes the answer.

There is a third option that removes the PATH question entirely: run it from a container with the whole toolchain pinned, behind a shell wrapper that keeps every flag working. That is its own page.

First run

Before analyzing anything, ask the tool what it found. --check reports what it discovered and what looks misplaced, then exits without analyzing.

$ python3 -m hpaanalyzer fixtures/good-chart --check
INPUT CHECK - /home/you/hpa-analyzer/fixtures/good-chart
-----------------------------------------------------------
  [ok]   Helm chart: Chart.yaml
  [ok]   Values: values.yaml
  [ok]   Templates: 7 file(s) under templates/
  [ok]   Workloads: 1 (Deployment)
  [ok]   Dockerfile: Dockerfile (Java 21)
  [info] Render mode: helm (rendered truth).

  => Looks complete. Analysis will run at full coverage.

Real output, exit code 0. If the directory is not a chart directory at all, --check ends with => Not a chart directory. Fix the path above and re-run. and exits 2.

This step exists because the most expensive failure mode of a static analyzer is a clean report produced from files it never read. Confirm the inputs first, then analyze.

Analyze

$ python3 -m hpaanalyzer fixtures/bad-chart
  [ok]   Helm chart: Chart.yaml
  [ok]   Values: values.yaml (+ 1 overlay: values-prod.yaml)
  [ok]   Templates: 3 file(s) under templates/
  [ok]   Workloads: 1 (Deployment)
  [ok]   Dockerfile: Dockerfile (Java 8u151)
  [info] Render mode: helm (rendered truth).
  [warn] 1 parse problem(s).

  GRADE F  (45.5/100)   11 critical, 11 high, 14 medium, 16 low
  Fix first:
    1. [HP004] HPA minReplicas > maxReplicas (invalid)  (templates/hpa.yaml)
    2. [HP025] HPA scales on memory for a JVM workload  [ASSUMED - verify]
    3. [HP050] Rendered Deployment sets spec.replicas while an HPA manages it  (templates/deployment.yaml)
    4. [RS002] Memory quantity uses 'm' (MILLI-bytes)  (values.yaml)
    5. [RS006] CPU limit below CPU request (invalid)  (templates/deployment.yaml)
    ... +17 more critical/high (see report)
  Full report: /home/you/hpa-analyzer/hpa_analysis_report.txt
  (60 findings, 7 proof tables, mode: helm)

Real output against fixtures/bad-chart. Note the exit code is 0 — finding problems is not an error. Exit codes only become non-zero when you ask for a gate; see CI gates.

The terminal shows a triage list. The detail — the arithmetic, the citations, the remediation, and the honest account of what was not checked — lands in hpa_analysis_report.txt beside you. Change that path with -o, add a clickable HTML version with --html, or get machine-readable findings with --json.

What comes back

A score, and its scale

A weighted count of what this run found, always printed alongside the number of categories it was computed over — because that is what makes two scores comparable.

A coverage section

What was analyzed and what was not. An unread file produces no findings, and this section is the only thing standing between that and a false clean bill of health.

Findings with a basis label

Every finding says whether it is OBSERVED, DERIVED or ASSUMED, so you can tell what the tool saw from what the tool guessed.

Proof tables

The HPA scaling arithmetic and the JVM memory budget, shown as tables you can check by hand rather than verdicts you have to trust.
