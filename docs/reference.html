Synopsis

usage: hpa-analyzer [-h] [-o OUTPUT] [--html [PATH]] [--summary | --full]
                    [--all] [--teach] [--stdout] [--quiet]
                    [--helm {auto,on,off}] [--kube-version VER]
                    [--assume-java VER] [--measured K=V[,K=V]] [--check]
                    [--fail-on {none,low,medium,high,critical}]
                    [--min-score N] [--require-coverage] [--json PATH]
                    [--cross-check] [--version]
                    directory

The single positional argument is the directory containing the chart, values and — optionally — a Dockerfile. It is required; running with no arguments is an argparse usage error that exits 2.

Three ways to invoke the same program:

python3 -m hpaanalyzer ./svc      # module form, used throughout these docs
python3 hpa-analyzer.py ./svc     # shim, identical behaviour
hpa-analyzer ./svc                # the container wrapper, see the Container page

Output & verbosity

FlagEffect
-o OUTPUT, --output OUTPUT Text report path. Default hpa_analysis_report.txt in the current directory.
--html [PATH] Also write a browsable HTML report with a filter, collapsible sections and a table of contents. PATH is optional and defaults to the -o path with a .html extension. Because the argument is optional, put this flag last or give it an explicit path.
--summary Short report: score, scorecard and the top CRITICAL/HIGH findings only. Mutually exclusive with --full.
--full Everything: expands LOW/INFO and includes the education appendix. Implies --all --teach.
--all Expand LOW/INFO findings to full detail. The default collapses them to one line each.
--teach Include the education appendix (HPA/JVM primer), omitted from the default report.
--stdout Also print the full text report to standard output.
--quiet Terminal only: print the one-line result and suppress the banner and fix-first summary. Does not change the report file.

Measured report sizes for fixtures/bad-chart (60 findings), with helm on PATH: --summary 167 lines, default 906, --all 1018, --full 1238. Without helm the same runs measure 170, 919, 1031 and 1251 — static mode is a longer report, not a shorter one. See Using it.

Analysis

FlagEffect
--helm {auto,on,off} Render via the helm binary. auto (default) uses it if it is on PATH; on requires it; off forces static analysis.
--kube-version VER Kubernetes version to render the chart for, e.g. 1.31.0. Passed to helm template --kube-version. Without it the tool derives one from the chart's own kubeVersion; without that, helm falls back to its compiled-in v1.20.0, which is EOL and will refuse most modern charts.
--assume-java VER Java version to assume when the base image tag hides it, e.g. 8, 8u151, 11.0.16, 17.
--measured K=V[,K=V] Replace an estimated JVM memory component with a number you measured. Keys: metaspace, codecache, threads, direct, gc, xss. Sizes take Ki/Mi/Gi or k/M/G; threads is a plain count. A measured component becomes OBSERVED, drops out of the budget's range, and stops being able to make the fit UNDETERMINED.
--check Input check only: report what was discovered and what looks misplaced, then exit without analyzing. Exits 2 if it is not a chart directory.

CI gates & machine output

FlagEffect
--fail-on {none,low,medium,high,critical} Exit 1 if any finding at or above this severity exists.
--min-score N Exit 1 if the score is below N. An ungradeable run also fails. The score is a weighted mean over the categories that could be assessed, so a run that loses an input is compared on a different scale — pair this with --require-coverage.
--require-coverage Exit 1 if any scoring category could not be assessed. Without it, deleting an input silently changes the scale the threshold is compared against.
--json PATH Also write machine-readable findings to PATH.

Ecosystem

FlagEffect
--cross-check Also run helm lint, kubeconform, kube-score and polaris (whichever are on PATH) and fold their verbatim output into the report. See the reproducibility warning.
-h, --helpShow help and exit 0.
--versionPrint hpa-analyzer 1.0.0 and exit 0.

Exit codes

Three codes, and nothing else. Every row below was measured.

CodeMeaningMeasured example
0Ran successfully. Findings are not errors. hpaanalyzer fixtures/bad-chart — 60 findings, grade F, exit 0
1A gate you asked for failed --fail-on high on fixtures/bad-chart; --require-coverage on fixtures/nojvm-chart
2Usage or IO error No arguments at all; ./nope → error: /nope is not a directory; --check on a directory that is not a chart

Only --fail-on, --min-score and --require-coverage can produce 1. If you want a run that never fails a pipeline, simply omit them.

JSON output

--json PATH writes an object with these top-level keys:

KeyContents
targetAbsolute path of the analyzed directory
modehelm or static
score, grade, gradedThe number, the letter, and whether a grade could be produced at all
score_coverageassessed, unassessed, weight_assessed, weight_total, complete, note
countsPer-severity totals: critical, high, medium, low, info
findingsThe array — shape below
coveragePer-input coverage rows, mirroring report section 2
cluster_probesThe "verify on your cluster" items
preflightWhat the input check found
cross_checkExternal validator results, populated only with --cross-check

A finding, verbatim from a real run:

{
 "rule": "CH002",
 "severity": "MEDIUM",
 "basis": "observed",
 "assumes": null,
 "category": "Helm Chart Structure & Hygiene",
 "title": "Chart apiVersion v1 (Helm 2 era)",
 "file": "Chart.yaml",
 "line": null,
 "detail": "Chart.yaml declares apiVersion: v1.",
 "why": "apiVersion v1 targets Helm 2, which reached end of life in Nov 2020 (no security fixes). ...",
 "fix": "Set apiVersion: v2 and manage dependencies via the 'dependencies' key ...",
 "math": null
}

severity is one of CRITICAL, HIGH, MEDIUM, LOW, INFO. basis is one of observed, derived, assumed; when it is assumed, the assumes field carries the guess in prose. line and math are frequently null — treat both as optional.

The ten scoring categories

Each starts at 100 and loses 25 per CRITICAL, 12 per HIGH, 6 per MEDIUM, 3 per LOW and 0 per INFO, floored at 0. The overall score is the weighted mean over the categories that could be assessed.

CategoryWeight
Resource Requests & Limits15
Horizontal Pod Autoscaling15
Java / JVM Container Fitness14
Cross-File Consistency (Chart ↔ JVM)14
Health Probes & Lifecycle10
Availability & Disruption Tolerance8
Dockerfile Quality8
Security Posture7
Kubernetes Templates & API Versions5
Helm Chart Structure & Hygiene4

The weights are the tool's opinion about what breaks production. Resources, HPA, JVM fitness and cross-file consistency carry 58 of the 100 points between them.

Project layout it expects

my-service/
├── Chart.yaml            # required
├── values.yaml           # required
├── values-prod.yaml      # optional overlays, analyzed as overlays
├── templates/
│   ├── deployment.yaml
│   ├── hpa.yaml
│   └── ...
└── Dockerfile            # optional since R8

The Dockerfile is optional: a JVM declared only in the pod spec — through JAVA_TOOL_OPTIONS, or a temurin/corretto image — is analyzed just as fully, and a chart that ships a Dockerfile but runs no JVM is no longer lectured about heap flags. Run --check to see exactly which files were found before you rely on any of this.

One chart per run. Subcharts under charts/ are rendered and recorded but never graded — see Scope for why, and for what that costs you.
